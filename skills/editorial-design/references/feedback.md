# Feedback, review and the next artifact

Use the existing project card, review events and version history rather than a second queue.

- Preserve the original human wording and its source, the exact before/after versions, and what
  visibly changed. A human-edited final artifact is an approved example only within the scope
  established by that edit; do not infer every unchanged feature is a permanent preference.
- Separate a one-off content correction, a scoped visual preference, a factual constraint and
  an untested performance hypothesis. Apply explicit corrections immediately in scope. Test
  inferred preferences on a subsequent related artifact, with counterexamples retained.
- Record an operational design decision: for example, enlarge the focal interface detail in
  this mobile demonstration. Avoid empty notes such as "make it premium". Preserve approved
  and rejected examples with provenance so a later agent can compare them directly.
- At the next relevant job, retrieve these examples, make the new artifact, and record the
  correction actually applied. After export inspection and delivery, link the evidence back to
  the original feedback event. Only then mark its application complete. Improvement remains
  unmeasured until a human response or comparable outcome supports it.

Publication authority and taste are different. If the user explicitly authorizes publishing
without a reply, follow their specified schedule and scope. Verify the final asset was available
on the review surface and re-read edits/holds before publishing. Silence can satisfy that
delegated release condition; it is not an endorsement, rating, or training example. A changed
version needs its own exact copy/media checks; a previous approval cannot silently cover it.
Unknown delivery is reconciled, never blindly repeated. Keep separate explicit holds intact
unless the user's instruction actually changes them.

Learning here means persistent examples, retrieval, decisions and subsequent verification.
Do not describe it as changing model weights or guarantee monotonic improvement. Remove a
superseded preference from active retrieval while retaining the original evidence in history.

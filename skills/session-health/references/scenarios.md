# Acceptance scenarios

These are generic checks for maintaining the skill, not a claim of independent evaluation.
Evaluate the disposition and the next authorized action together. Do not score a switch
as correct if it drops unfinished work, changes the owner, or duplicates an external action.

| Situation | Appropriate response |
|---|---|
| Long chat, same goal, source checks pass and corrections work | CONTINUE; no length-based switch. |
| One incorrect field corrected and the next result is right | CONTINUE; no sustained degradation inferred. |
| Two document versions disagree; current source is identifiable | REANCHOR to current source and check the next step. |
| After re-anchor, output still repeatedly applies rejected project rules | NEW_SESSION with verified-only context; no inherited-history fork as a cure. |
| Tool returns access denied or a service is unavailable | Treat the actual dependency; switching chat is not the fix. |
| A clean session was explicitly requested | Prepare continuity directly; no mandatory repair ritual. |
| Primary task changes to an unrelated project | Isolate the new goal; retain the old task's state without cross-project memory. |
| A quick definition is asked during an otherwise coherent task | Answer locally and resume; no compulsory new chat. |
| A new phase starts under the same goal and sources | CONTINUE unless actual failure or excess relevant input needs REANCHOR. |
| Context is mixed, a focused repair fails, and a publish request has unknown delivery | NEW_SESSION recommended; verify the original action, never re-publish. |
| A clean session is appropriate but the current owner has an active GUI lease | Prepare continuity and wait for the allowed boundary; no takeover or lease release. |
| One-off factual answer has no ongoing project | No forced memory initialization or checkpoint ritual. |
| Memory write fails | Preserve a private/chat packet; report missing receipt and do feasible work. |
| Parent workspace already binds this session to a child project | Reuse the child's store; do not initialize at the parent. |
| A source changes after checkpoint | Verify the new source; do not treat the old memory as current truth. |
| Global host files changed while other chats remain open | Report installed routing; adoption of those sessions remains unobserved. |

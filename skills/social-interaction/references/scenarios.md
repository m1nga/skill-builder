# Contribution choices

| Source situation | Useful contribution | Boundary |
|---|---|---|
| Opinion or debate | Explain a reason, condition, counterexample or trade-off | Do not disagree merely to sound original |
| Visual work | Name a visible choice and its effect | Do not invent author intent or critique an unrequested redesign |
| Launch or demo | Clarify who can try it and remove a concrete trial obstacle | Viewing a clip is not testing the product |
| Explicit help request | Give an observation, bounded suggestion or usable resource | Ask only for a missing detail that changes the help |
| Pain point | Answer the actual problem; recommend a verified fit if useful | Do not turn every complaint into a product pitch |
| Process or setback | Discuss the author's goals and choices | Do not invent shared personal experience |
| Professional resource | Add relevant knowledge or make a permitted connection | A professional contact is not automatically a sales lead |
| Joke or celebration | Respond naturally, briefly if enough | Do not attach a lesson or call to action by default |
| Criticism or support issue | Address the substance and state the actual next step | Do not invent a fix, deadline or apology for unverified facts |
| Old invitation or thanks | Honor the actual relationship state | No repeat outreach without a relevant new condition |
| Unfamiliar mixed case | Explain the contribution in plain language | Extend the taxonomy only when useful; no forced category |

A hypothetical disagreement: an author equates simpler visual styling with better design.
A useful reply might question whether readers can find the offer and next action, while
acknowledging the stronger visual direction. The point is the decision criterion, not a
reusable sentence to post under unrelated designs.
